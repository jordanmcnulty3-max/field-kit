# Heat, Shelter and Winter Pack (v7.3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the second Survival content pack: fourteen source-checked heat, shelter and winter topics (twelve new, two deepened), two checklists, a wind chill tool backed by sourced data, redrawn and new diagrams, released as v7.3.

**Architecture:** Content is JSON under `src/survival/` and `src/checklists/`, exactly as in v7.2. One framework addition: tool data files may carry a validated `grid` (a transcribed chart), used by a new Survival tool `windchill`. Nothing else in the app changes.

**Tech Stack:** Vanilla JS on `window.FK`, Python build and validator, `unittest` + pytest/Playwright at 360×640.

**Spec:** `docs/superpowers/specs/2026-11-18-heat-pack-content-plan.md`, under `docs/superpowers/specs/2026-11-17-v7-survival-knowledge-center-design.md` (sections 5 and 6 bind). Read both.

## Global Constraints

- Edit `src/`, `figs/`, `tools/`, `tests/`, `docs/`, `build.py` only. Root `index.html`, `sw.js`, `manifest.json`, `leaflet.*` are build output; only Task 11 rebuilds them.
- The repository is public: never write the group's home town into tracked files; say "Central New York".
- Every number, time, distance, temperature and procedure in content comes from a source that was actually opened and is recorded in `docs/content-review.md`. No Firecrawl; built-in search, then fetch pages the search returned; never a constructed URL. After each fetch confirm the page is the one asked for.
- Existing checked text binds new text: `surv-fire`, `surv-shelter`, `surv-priorities`, `surv-water-winter`, `surv-water-in-the-house`, `surv-wells-without-power`, and Emergency protocols `p:hypothermia`, `p:frostbite`, `p:carbon-monoxide`, `p:burns`, `p:heat-illness`. New text agrees with them or logs a question in `docs/decisions-for-jordan.md` section D (next free number is 37). A checked protocol is never edited in this pack.
- Medical treatment is linked, not restated.
- Where sources disagree, use the more cautious one and log a D question. Fuel-burning heaters: operating guidance under the strictest conditions any opened agency source sets; name any agency or New York rule that says not to use them indoors (spec 9.10).
- No 911 or dial control. No drawings of edible plants. No instructions aimed at harming people. Clove hitch, taut-line, square knot and sheet bend stay text-only.
- US units first, metric in brackets. Plain, direct voice; imperative steps. State rules (firewood movement, open burning, fuel storage limits) are stated as applying in normal times, with New York's named.
- Safety-critical topics stay visible under every filter value. Topic tables fit 360 px or scroll with the "Swipe sideways" cue (the shipped-data test checks).
- Stored or typed values that are unknown or malformed are ignored, never rendered; every string reaching markup goes through `FK.esc`. 48 px touch targets in Survival. Night mode on every new screen.
- Content workers stage only their own files by name; never `git add -A`; no stash, reset, rebase or amend.
- Tests: `python3 -m unittest tests.test_validate && python3 -m pytest tests -q`; any console error fails. Commit after every task with the session's attribution trailer. Branch `heat-pack`. No push to `main` before Task 11.

## Review Focus

1. Wind chill inputs that are blank, non-numeric, decimal, negative wind, or huge (`""`, `"abc"`, `12.7`, `-5` mph, `1e9`): the tool shows a plain message, never `NaN`, `Infinity`, a wind chill, or a frostbite band. Task 2.
2. Inputs between chart cells and on its edges: the band is read at the next colder chart temperature and the next higher chart wind; the four corner cells and every edge cell return their own band; one step outside any edge shows "Off the National Weather Service chart" and no figure. Task 2.
3. `FK_DATA.tooldata.windchill` missing, draft, or with a damaged grid (ragged row, band not in the allowed set, temps not descending): the validator rejects it at build, and at run time the tool says its numbers are not available and shows nothing. Tasks 1 and 2.
4. `surv-fire` and `surv-shelter` change category: pins, recents and search keys saved by v7.2 still open them; Basics still lists its remaining topics; a v7.2 backup restores on v7.3. Task 10.
5. Filters: every protected topic is listed under all 15 Where × When combinations; topics tagged `when: cold` are hidden only under Warm; the heat category header and its fourteen rows do not overflow at 360 px. Task 10.

Shared names:

- Tool name `windchill`, key `u:windchill`, address `#/survival/tool/windchill`, label "Wind chill".
- Tool data `windchill`: `values` = `{ c0, cT, cV, cTV, exp }` (the NWS formula constants, each `{ value, unit, note }`; names fixed here, numbers from the opened source), and
  `grid: { temps: number[] (°F, strictly descending), winds: number[] (mph, > 0, strictly ascending), chill: number[][], bands: number[][] }`
  where `chill[w][t]` and `bands[w][t]` are the chart cell for `winds[w]`, `temps[t]`; a band is `0` (no frostbite time shaded) or a number of minutes from the chart's legend. The allowed band set is `grid.bandMinutes: number[]` (ascending, each > 0), read from the chart legend.
- Formula: `chill = c0 + cT·T − cV·V^exp + cTV·T·V^exp`, rounded with `Math.round`, computed only when `min(temps) ≤ T ≤ max(temps)` and `min(winds) ≤ V ≤ max(winds)`.
- Band lookup: the next colder and windier cell: the largest `temps[i]` that is ≤ T and the smallest `winds[j]` that is ≥ V.
- New topic ids: `surv-heat-out`, `surv-carbon-monoxide`, `surv-wood-stoves-fireplaces`, `surv-portable-heaters`, `surv-generators`, `surv-store-fuel`, `surv-firewood`, `surv-unheated-house`, `surv-dress-for-cold`, `surv-sleep-warm`, `surv-winter-storms`, `surv-wind-chill`. Checklist ids: `home-heat-kit`, `vehicle-winter-kit`.

**Reviewer** (did not write the batch). Re-open every source in the record. For each topic compare every number, table cell, "never" and step order with the source; check agreement with the binding topics and protocols in Global Constraints; check every link key; check tags against the spec; check tables at 360 px in the built app. Report findings as Critical (unsafe or contradicts a source), Important (wrong, misleading or hidden), Minor.
