# v7.8 Tactical map Implementation Plan

> **Changed during the build:** QR share and receive (plan Task 11) was dropped from v7.8 by the owner and replaced by iPhone first-test fixes; the track climb figure was dropped. See `docs/v7.8-rulings.md` for every decision made during the build.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Tactical the single-phone features of ATAK (markers with kinds, tools, navigation, import/export, QR hand-off, auto declination) with no browser pop-ups and full tests.

**Architecture:** The map stays crosshair-driven. Marker and shape data move out of `src/app.js` into one data module that owns storage and events; pure maths and file formats live in global `const` modules with no DOM; each screen feature is its own file. All sheets are `<dialog>` elements opened through one helper that ties them to the router's history so Back closes them.

**Tech Stack:** Vanilla JavaScript (IIFE modules on `window.FK`, concatenated by `build.py`), Leaflet (vendored), Python Playwright + pytest, no bundler.

**Spec:** `docs/superpowers/specs/2026-11-20-v7.8-tactical-map-design.md`. Read it with this plan. Project rules: the project doc `claude/FIELD-KIT-STATUS.md` rules 1 to 13 (the controller pastes the relevant ones into each task brief).

## Global Constraints

- Edit `src/`, `figs/`, `tools/`, `tests/`, `docs/`, `vendor/`, `build.py` only. Never commit root `index.html`, `sw.js`, `manifest.json`, `leaflet.*`. Build for tests into a temp folder (`python3 build.py /tmp/out`); the test harness does this itself.
- Branch `tactical-map`. Never commit or push to `main`. Stage files by name. Commit after every green step.
- Fully offline. No new network host. No `prompt()`, `confirm()` or `alert()` anywhere in `src/` when the release ends.
- No new browser API that Safari on iPhone lacks without a fallback in the same commit. Each new API (`navigator.share`, `getUserMedia`, `<dialog>` features, `DOMParser`, anything else) is checked on a page that was opened (MDN, caniuse or webkit.org) and logged with its iOS version in `docs/v7.8-rulings.md`. Do not use `AbortSignal.timeout`, `CompressionStream` or `BarcodeDetector` in new code.
- Web research: built-in search and fetch only. Fetch only URLs exactly as a search returned them. Never use the Firecrawl or Bright Data tools.
- Every number from outside (magnetic model, symbol colours, reference distances) comes from an opened source recorded in `docs/content-review.md` under a new "v7.8 Tactical" heading.
- Public repo: fixtures use coordinates near 43.0, -76.0 only as round numbers, never a real address; docs say "Central New York".
- Search: `tests/fixtures/search_v77_on_screen.json` must not change. If a change to `SCREENS` in `src/search.js` moves a pin, undo the change to `SCREENS`.
- Words on screen: "Marker" (not waypoint), "Saved maps" (offline tiles), "Area" (drawn shape). No internal wording (task numbers, "D216") in text users see.
- Every new screen works at 360 px wide, day and night mode. Touch targets at least 44 px.
- Text put into the page from a name, note or imported file goes through `FK.esc` or `textContent`. Never `innerHTML` with raw user text.
- The app only records what the user marks; no text advising action against a person.
- Each task brief tells its worker: tests first, commit early, do not run the full 8-minute suite (run the named test files), and do not touch files outside the task's list.

## Review Focus

1. **Storage full while saving a marker or shape.** Expect: the item stays on screen, a message says it was not saved (existing `FULL_MSG`), nothing else is lost. Test in Task 2.
2. **A hostile or broken import file** (markup in names, 50,000 points, not XML, a 6 MB file). Expect: names shown as text, shapes thinned to 200 points, a plain refusal, no script runs, app still works. Test in Task 10.
3. **No GPS fix ever** (indoors, permission refused). Expect: every tool, the list, import, export and QR work; distances "from you" are simply absent; navigation says it is waiting for a position. Tests in Tasks 4, 6, 8.
4. **Back pressed in the middle of a tool with unsaved points.** Expect: with two or more unsaved points a confirm sheet ("Discard this route?"); otherwise the mode just closes; never a stuck bar or a half-saved shape. Test in Task 6.
5. **QR codes scanned out of order, twice, or mixed from two different shares.** Expect: order does not matter, repeats are ignored, a code from another share is refused with "That code is from a different share", nothing is added until all parts are in. Test in Task 11.
6. **A marker where MGRS does not exist** (above 84° N) or on the date line. Expect: latitude and longitude shown instead of a grid, no "null", shapes do not draw across the whole world. Tests in Tasks 3 and 4.
