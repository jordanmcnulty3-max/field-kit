# v7.8 "Tactical map" design

> **Changed during the build:** QR share and receive (plan Task 11) was dropped from v7.8 by the owner and replaced by iPhone first-test fixes; the track climb figure was dropped. See `docs/v7.8-rulings.md` for every decision made during the build.

Date: 2026-11-20. Status: approved by Jordan 2026-11-20 with one change (friend and hostile markers added). Branch: `tactical-map`.

## Why

Jordan wants Tactical to do what ATAK does, inside Field Kit, so nobody in the group has to run ATAK
("I don't want to run ATAK. I would like to keep this all self-contained within this app"). The map,
the compass and waypoints are what he calls extremely important. Tactical has not had a design pass,
a review or a phone-size walk-through since v5.

ATAK's team features (seeing each other, chat, sending markers live) need a link between phones. That
is the v8 Meshtastic release and is not in this one. v7.8 is **everything ATAK does that one phone can
do alone**, plus handing data to another phone with no network.

Order agreed with Jordan on 2026-11-20: this Tactical pass first (v7.8), then iPhone support, then
Ballistics improvements. iPhone support is not a goal of v7.8, but nothing in v7.8 may make it harder
(see Constraints).

## Goals

1. A person can mark, label, find, edit and delete points on the map without leaving the map.
2. A person can measure, plan a route, mark out an area and draw a range ring.
3. A person can walk to a point using a large, glanceable display.
4. A person can type a grid and have the map go there.
5. Plans made elsewhere load in (KML, GPX) and plans made here load elsewhere.
6. One phone can hand its markers, routes and areas to another phone with no network.
7. True bearings without typing a declination.
8. No browser pop-ups anywhere in Tactical. Tactical looks like the rest of the app.
9. Every feature above has tests. Tactical goes from 8 tests to full coverage of what it does.

## Not in this release

- Live team positions, chat, any radio or network link (v8).
- Any change to the ballistics maths or new ballistics features (next Tactical release). The two
  ballistics pop-ups are replaced because that is interface, not maths.
- iPhone fixes (compass permission, `AbortSignal.timeout` fallback, wake lock). Next release.
- Recce (its own later release).
- A contour overlay on satellite imagery. No source on the USGS server; needs its own design.
- Elevation profiles, line-of-sight, viewsheds. They need elevation data the app does not have.
- Any symbology beyond the marker kinds listed under Data (no unit-type, weapon or target symbols).
- Measuring the offline save size for USGS Imagery (cannot fetch tiles from a build session).

## Anti-goals

- A feature that only works with a network. Everything here works in airplane mode on saved map areas.
- A gesture that needs precision. Gloves, cold hands, rain. Nothing depends on a long-press or on
  hitting a 10 px handle.
- Losing data. Existing waypoints, tracks, saved areas and profiles survive the update untouched, and
  a v7.7 backup still restores.
- More chrome on the map than map. The map stays the largest thing on the screen.

## Constraints

- Standing rules in `claude/FIELD-KIT-STATUS.md` (rules 1 to 13) and its Decisions list bind this release.
- Fully offline; one built `index.html`; no runtime dependency on any server but the map tile hosts.
- New third-party code is vendored in `vendor/`, with its licence file, and must be permissively
  licensed (MIT, BSD, Apache-2.0, ISC or public domain).
- **iPhone-neutral.** No new use of an API that Safari on iPhone lacks without a fallback written in
  the same change. Each such API is checked against a page that was opened (MDN, caniuse, WebKit),
  with the version, and recorded in `docs/v7.8-rulings.md`. No iOS behaviour from memory.
- **Search (rule 13).** New screens may be added to search only if the 123 pinned searches in
  `tests/fixtures/search_v77_on_screen.json` are unchanged. If a new entry moves a pin, drop the entry.
- Every number comes from an opened source recorded in `docs/content-review.md` (applies to the
  magnetic model and to pace figures).
- Public repo: test fixtures and docs say "Central New York" and use no home coordinates.
- No instructions or symbology for use on people.

## Approaches considered

**A. One tools sheet on the map, crosshair-driven (chosen).** The map keeps its current model: the
crosshair at the centre is the cursor, and one button acts on it ("Mark" today). A single Tools button
opens a bottom sheet listing the tools. Each tool runs in a mode with a bar at the bottom: "Add point",
"Undo", "Done". Points are placed by moving the map under the crosshair and pressing a large button.
Trade-off: slower than tapping the map directly for many points; but it is precise, works with gloves,
never fights the pan gesture, and is the same on Android and iPhone. It builds on what the code does now.

**B. Tap-on-map drawing with a vendored drawing library (Leaflet-Geoman or Leaflet.draw).** Faster to
sketch with a fingertip, and less code to write. Rejected: touch handles are small, a tap to place a
point is easily confused with a tap to pan or open a marker, the libraries add 100 to 300 KB to a
2.18 MB page, and their iPhone touch behaviour is untested by us.

**C. Split Tactical into more tabs (Map, Markers, Routes, Position, Ballistics).** Simple to build.
Rejected: Jordan's first goal is doing things on the map; sending him to another tab to manage what he
is looking at is the current weakness (waypoints live under Position today).

Jordan handed over the how ("open to suggestions"); A is the builder's call.

## Design

### 1. Data

All in `localStorage` through the existing `store`, validated on load as waypoints are today.

- **Markers** (the existing `wps` key, extended; old records load unchanged):
  `{ id, name, lat, lon, alt, t, kind, note }`. `kind` is one of: `point` (default), `camp`, `vehicle`,
  `water`, `cache`, `hazard`, `rally`, `observe`, `medical`, and four **affiliation** kinds: `friend`,
  `hostile`, `neutral`, `unknown` (Jordan asked for friend and hostile on 2026-11-20; neutral and
  unknown are the builder's addition, because what is seen is often not yet known to be either).
  A missing or unrecognised `kind` reads as `point`.
  `note` is free text, 500 characters at most. The word in the interface is **Marker** on the map and in
  the list; "waypoint" stays in search keywords and in GPX/KML export.
- **Shapes** (new key `shapes`): `{ id, type, name, pts, r, t }`, `type` is `route` (2 or more points),
  `area` (3 or more points, closed) or `ring` (one centre point and `r`, a list of one to three radii
  in metres: one ring shape draws up to three circles and is named, moved and deleted as one thing).
  At most 200 points per shape and 100 shapes; the interface says so when the limit is reached.
- **Declination** (existing `decl` key plus new `declMode`: `auto` or `manual`). An existing non-zero
  typed value keeps `manual`; otherwise `auto`.
- **Units** (new key `distUnit`: `metric` or `us`). Default `metric`, as the map shows today.
- **Navigation target** (existing `target` key, widened): a marker id, or a route id with the index
  of the next point, or a bare point (used by "Back to start"; never saved as a marker). A stored
  target that matches nothing is dropped on load, as today.
- **Names on screen.** The store key `areas` already means saved offline maps. On screen those are
  called **Saved maps** everywhere; **Area** means a drawn shape. The store key does not change. The
  search entry "Saved areas" is retitled only if the 123 pinned searches stay unchanged; its keywords
  keep "saved areas" either way.
- Backup and restore carry all of these (the backup already writes every stored key; only the restore
  message changes). A backup from v7.7 restores into v7.8. The restore
  confirmation text names markers, routes and areas.

### 2. Map screen

```
+--------------------------------------+
| USGS Topo        [rec 1.2 km]        |
|                                  [L] |  layers
|                                  [o] |  follow me
|                +                 [T] |  tools   (new)
|                                  [=] |  list    (new)
| |--- 200 m ---|                      |  scale bar (new)
+--------------------------------------+
| 18T VN 12345 67890      [ Mark ]     |
| 412 m at 073 deg true from you       |
+--------------------------------------+
```

- **Controls:** four buttons: Layers, Follow me, Tools, List. Track recording and Save for offline
  move into Tools. The recording chip stays on the map while a track records, and tapping it opens
  Track recording.
- **Scale bar** bottom left, in the chosen units.
- **Mark** opens the marker sheet (below) instead of a browser prompt. The marker is created only on Save.
- **Press and hold on the map** still adds a marker at the pressed point, as today, now through the
  marker sheet. Nothing depends on it.
- **Tap a marker** opens the same sheet for that marker, replacing the Leaflet popup.
- **Tap a route, area or ring** opens the shape sheet: name, length or area or radius, Rename, Delete,
  and for a route "Walk this route".
- **Tools sheet** (bottom sheet, large rows): Measure, Route, Area, Range ring, Go to grid,
  Track recording, Save map for offline, Import, Export, Share by QR, Receive by QR.
- **List sheet:** Markers and Shapes in one list with a filter by kind, sorted nearest first when
  there is a fix, otherwise newest first. Each row: icon, name, grid, distance and bearing. Tap a row to
  centre the map on it and open its sheet.

### 3. Marker sheet

One sheet for new and existing markers: Name (prefilled "WP n"), Kind (two rows of icon buttons with
labels: nine places, then the four affiliations), Note, the grid (tap to copy), distance and bearing from you; buttons **Save**, **Go to** (start
navigating), **Move**, **Delete**. Move closes the sheet and puts the map in a move mode: a bar says
"Move the map until the crosshair is on the new spot" with Place and Cancel. Delete uses the shared confirm sheet.

The four affiliation markers use the standard frame shapes and colours so they read the same as in
ATAK: friend a blue rectangle, hostile a red diamond, neutral a green square, unknown a yellow
quatrefoil. Shape carries the meaning as well as colour, so they stay distinct in night mode and for
a colour-blind reader. The shapes and colours are confirmed from an opened source before drawing and
recorded in `docs/content-review.md`. An affiliation marker's sheet and list row show when it was
marked and how long ago ("Marked 14:32, 2 h ago"), because a sighting goes stale; the marker itself
fades to an outline after 24 hours and is never deleted automatically. The app only records what the
user marks: it gives no advice on what to do about a marker.

Icons are simple line drawings in the app's existing stroke style, drawn for this release, each
recognisable at 24 px in day and night mode without its label. They are judged image-first by a
reviewer; one that fails is replaced by the plain point with its label.

### 4. Tools

- **Measure.** Add point at the crosshair; from the second point on, the bar shows the leg distance and
  bearing and the running total. Undo, Clear, "Save as route", Done. The last point is always joined
  to the live crosshair, so the reading updates as the map moves (range and bearing line). With no
  point placed, the existing "from you" reading under the grid is the measurement.
- **Route.** Same interaction as Measure, ends in a named route. The shape sheet shows total length and
  each leg's distance and bearing.
- **Area.** Three or more points; shows perimeter and area (acres and hectares, or square metres when small).
- **Range ring.** Centre at the crosshair or at a chosen marker; radius typed in the chosen units; up to
  three rings per centre (for example 100, 300, 500 m). A ring is geodesic-correct to within 1% at
  radii up to 50 km at New York latitudes; larger radii are refused with a plain message.
- **Go to grid.** One field accepting what `GEO.parseAny` accepts today (MGRS, decimal degrees,
  degrees-minutes-seconds). The map centres there and offers "Mark here". A grid it cannot read gets
  the existing help text. Follow-me turns off.
- **Track recording.** As today, plus elapsed time and average moving speed. Climb is shown only if GPS
  altitude is present on at least 90% of points, labelled "approximate (GPS altitude)". A recorded
  track can be saved as a route.
- **Walk this route / Go to.** Navigation targets either a marker (as today) or a route. On a route the
  target is the next point; it advances when within 25 m of the point (or the fix accuracy, if larger),
  and the display says "Point 3 of 7" with **Previous** and **Next** buttons, because a point can be
  passed without the phone noticing (app in another tab, poor fix). While a target is set, GPS keeps
  running in every tab of the app, as it does while recording. The screen is not forced on; the
  existing "Keep screen on" switch is shown beside the navigate display.

### 5. Navigate display

Position tab, top of the screen when a target is set, and a compact strip on the map:

```
        ^            RALLY 1
      (arrow)        412 m   073 deg true
                     Turn 20 deg right
                     about 6 min at your pace
```

- A large arrow that points at the target relative to the phone's heading. With no compass heading it
  shows the bearing as a number and says "No compass: bearing shown as a number" instead of an arrow
  that would be wrong.
- Time to go uses the average of the last 60 seconds of GPS speed when moving faster than 0.5 m/s;
  otherwise no time is shown. No pace-count feature in this release (no source opened yet).
- "Back to start": when a track is recording, one button sets the target to the track's first point.
- The existing bearing line on the map stays.

### 6. Compass and position

- **Declination worked out from the position** using the current World Magnetic Model coefficients
  published by NOAA (public domain). The coefficient file, its epoch and its valid-until date are
  recorded in `docs/content-review.md`. The implementation is tested against NOAA's own published test
  values for the model, to the tolerance NOAA states. The Position screen shows "Declination 12.4° W
  (worked out from your position, model valid to <date>)" with a switch to type it by hand. After the
  model's valid-until date the screen says the model is out of date and to check a current map; it
  still shows the value. **If the coefficient file or the test values cannot be opened in the build
  session, this item is dropped and declination stays typed by hand** (rule: no number without an
  opened source).
- Heading text is larger (readable at arm's length), with magnetic/true stated beside it.
- **Position as text:** one button copies and shows a block to read aloud or paste into a message:
  grid, latitude and longitude, altitude, accuracy, time (local and Zulu). Uses the Share sheet where
  the browser has `navigator.share`, otherwise copy.
- The Waypoints block on Position becomes a short "Markers" summary with a button to the map's list;
  "Mark here" and "Add by grid" stay on Position because they are useful with the map closed.

### 7. Import and export

- **Export:** one dialog. Choose GPX or KML; choose what to include (markers, routes and areas, the
  recorded track). KML now carries routes (LineString), areas (Polygon) and rings (Polygon of 72
  points), marker notes (description) and kind (in the name's style id and as ExtendedData). GPX carries
  markers (wpt with `sym` and `desc`), routes (rte) and the track (trk); areas and rings are written as
  closed routes because GPX has no polygon.
- **Import:** pick a `.gpx` or `.kml` file. The app reads it with the browser's XML parser, shows a
  count ("12 markers, 2 routes, 1 area") and asks before adding. Points, LineStrings, Polygons (outer
  ring only), `wpt`, `rte`, `trk` are read; a track is imported as a route, thinned to 200 points.
  Everything else is skipped and counted ("3 items skipped: not a point, line or area"). KMZ (zipped
  KML) is not read; the message says to export KML instead. Names and notes are treated as text, never
  markup. Files over 5 MB are refused. Import never replaces existing data; an item identical in
  type, name and coordinates (to 5 decimal places) to an existing one is skipped and counted.
- **Field Kit's own files restore exactly.** Export writes each item's Field Kit type, kind and ring
  radii as extra data (KML `ExtendedData`, GPX `extensions`). Import reads that first, so an area
  comes back as an area and a ring as a ring from either format, and re-importing your own file adds
  nothing. Other apps ignore the extra data and see ordinary points, lines and polygons.

### 8. Phone-to-phone by QR

- **Share by QR:** choose items (or "everything"), the phone shows one or more QR codes full screen at
  maximum brightness hint ("turn your brightness up"). **Receive by QR:** the camera opens, reads the
  code or codes, shows the count and asks before adding, with the same duplicate rule as import.
- **Format:** a compact text payload, version-tagged (`FK1:`), with coordinates rounded to 5 decimal
  places (about 1 m), kind as one letter, names and notes included. Each code carries at most about
  1,200 bytes so it scans on an ordinary phone screen; larger sets are split into numbered codes
  ("2 of 4") shown one at a time with Next, and the receiver says which numbers are still missing.
  A checksum per code; a damaged or foreign code is refused with a plain message.
- **Libraries:** shipped as separate files beside Leaflet and added to the service worker's precache
  list, not inlined into `index.html`. A vendored QR generator and a vendored QR decoder that works on camera frames in plain
  JavaScript, so it does not depend on `BarcodeDetector`. Camera access uses `getUserMedia`.
- **Research gate:** before building, open and record (a) each library's licence and size, (b) camera
  access for a web app installed to the Home Screen on iPhone, with the iOS version. If the camera
  cannot be confirmed for an installed web app on iPhone, Share by QR still ships and Receive ships on
  Android with a plain "not available on this phone" message elsewhere; that limit is logged for Jordan.
- **Fallback when no camera or permission is refused:** Receive offers "Import a file" instead.
- This is the highest-risk item. It is built last, on its own, and is **the item to drop** if the
  release grows too large: export and import by file already move data between phones over any
  messaging app.

### 9. Pop-ups and layout

- One shared sheet helper replaces all six `prompt()` and `confirm()` calls (name a marker, delete a
  marker, clear a track, delete a saved map, name a ballistics profile, delete a ballistics profile).
  It is a `<dialog>` in the app's style: focus goes to the field or to Cancel, Enter confirms a name,
  Escape and the phone's Back button cancel (through the router's history, so it is testable; the
  same mechanism closes the Tools, List, marker and shape sheets and leaves a tool mode), destructive buttons are labelled with the action
  ("Delete marker") and are never the default. The helper lives where Emergency and Survival can use
  it later; they are not changed in this release.
- Tactical's headings, blocks and spacing are brought to the v7.6 home standard (small muted capitals,
  space above each section). Position and Ballistics get this as a restyle only: no field moves in
  Ballistics, no maths changes.
- Every new screen is checked at 360 px wide, day and night mode, and with the largest text size setting.

### 10. Units

A "Distances" setting in Settings: Metric (m, km) or US (yd under 1,000 yd, then mi). It applies to the
map readout, scale bar (custom-drawn; Leaflet's has no yards), tools, lists and navigate display.
The Position list, which shows km and miles together today, follows the setting too. Altitude stays in feet and speed in mph as
today; ballistics units are untouched.

## Code structure (left to the builder, with these limits)

- `src/map.js` (459 lines) is split rather than grown: map core and layers stay; markers, shapes and
  tools, navigation, import/export, QR share, and the sheet helper each get their own file, added to
  the list in `build.py`. Marker and shape state moves out of `app.js` into one module that owns the
  data and emits the existing `wps` event plus a `shapes` event.
- Pure functions (geodesic destination point and ring, polygon area, route length, the magnetic model,
  the QR payload encode/decode, GPX/KML read and write) take plain values and are tested without the
  map.
- Tests are written first for every pure function and every screen behaviour (Playwright, as the
  existing suite does). Tile requests are aborted in tests as `tests/test_map.py` does now.

## Testing and review

- **Scope of tests.** Everything v7.8 adds or changes, plus the existing map and position behaviour
  it sits on: offline save and delete, GPS on/off rules, compass display, track recording, backup and
  restore of Tactical data. The ballistics solver's tests against published drop tables belong to the
  ballistics release; v7.8 tests only that the ballistics screen and profiles still work.
- **Distance accuracy.** The existing distance function (a sphere, not the ellipsoid) is kept. It must
  agree with a geodesic reference to within 0.5%, which is 5 m in a kilometre. Screens never show more
  precision than that supports.
- Geometry checked against published values: distances and bearings against a geodesic reference
  recorded in `docs/content-review.md`; the magnetic model against NOAA's test values.
- Round trips: export then import returns the same markers, routes and areas; QR encode then decode
  returns the same; a v7.7 backup restores.
- Data safety: a store holding v7.7 waypoints, track, areas and profiles opens in v7.8 with nothing
  lost; malformed records are dropped without stopping the app.
- Search: the 123 pinned searches are unchanged.
- Reviews, as in v7.7: an independent reviewer per batch; one reader through the whole branch; an
  image-first review of the thirteen marker icons; a final reviewer who builds the app and uses it at
  phone size as a person in a situation (planning a route to a rally point at home; walking it in the
  woods at dusk in night mode; handing the plan to a second phone).
- **What a build session cannot test:** real GPS, a real compass, a real camera reading a real screen,
  map tiles. Each of those goes on Jordan's phone-check list, stated plainly as not seen working.

## Build order

1. Sheet helper; replace the six pop-ups. Data module for markers and shapes with migration tests.
2. Marker sheet, kinds and icons, list sheet, scale bar, units.
3. Tools: Measure, Route, Area, Range ring, Go to grid. Track additions.
4. Navigate display; route navigation; back to start.
5. Declination from position (research gate first); position as text; Position restyle.
6. Import and export.
7. QR share and receive (research gate first).
8. Ballistics restyle only; whole-branch read; icon review; final drive; release.

Each step leaves the app releasable. If the release has to be cut, it is cut from the bottom of the list.
